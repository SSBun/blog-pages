Swift Under a Microscope: Compiling Procedure

SSBun
2023-05-09 (Updated: 2023-05-09)
Compiler, LLVM, Swift

Starting today, I will begin releasing a series of blog posts about Swift implementations at low-level. These articles will document my insights and learning process. It may take me a long time to complete, as I have other work to do, and I am also writing these blogs with my limited English skills.

The first article will introduce the entire compiling process for iOS projects and Swift code. Additionally, there are many other concepts that we should be familiar with beforehand. I will be discussing the structure of an iOS project and how it is built.

iOS Project Construction

There are four key concepts in our iOS projects, Workspace, Project, Target and Scheme. I will introduce theirs effect below.

Target

A target can generate a product finally, like: Executable, dynamic library, static library, Widget extension else others. Every target has its own building settings and configurations. You can separately run a target using the specific configuration. Xcode will automatically create a scheme for every added target.

We usually add other targets besides the main app target for creating frameworks or developing Widget extensions or other plugins.

Scheme

A scheme is a collection of settings that specifies the target to build for a project, the build configuration to use, and the executable environment to use when the product is launched. When you open or create an project, Xcode automatically crates a scheme for every targets, The default scheme is named after your projects.

Project

In Xcode, a project is a container for all the files, resources and settings required to build one or more products. A project typically contains multiple targets, which are separated to products or components of the project that can be build independently.

Project in Xcode provides a structured environment for developing software and organizing your code and resources. They allow you to group related files together, set build configurations, manage dependencies, and more.

Workspace

You can create new projects or add existed projects to a workspace, allowing all of the projects to interact with each other by setting up dependencies and sharing code or assets. A workspace is a collection that groups multiple related projects for easy management.

Swift Compiling Procedure

Compiler Compiling Procedure

A normal compiler usually contains three modules, Frontend, Optimizer and Backend.

  • Frontend: The frontEnd will process all source code, do lexical analysis and semantic analysis, generate AST (abstract sematic tree) and export IR (intermediate language).
  • Optimizer: The optimizer will do some optimization to the IR generated by frontEnd.
  • Backend: The backEnd will convert the optimized IR to machine code for various hardware platforms (x86_64, arm64).

LLVM

Broadly speaking, the LLVM contains all three modules above. Narrowly speaking, the LLVM specially refer to the BankEnd module.

The LLVM has multiple sub-projects:

  • LLVM Core: The LLVM Core libraries provide a modern source- and target-independent optimizer, along with code generation support for many popular CPUs.
  • Clang: Clang is an LLVM native C/C++/Objective-C compiler.

Clang

The Clang is a C/C++/Objective-C compiler built in LLVM.

The main procedure:

  • Pre-process: The Clang preprocessor will extend all include, remove comments, do conditional complication and remove or replace macros. C files will be converted to .i files, C++ to .ii, Objective-C to .mi and Objective-C++ to .mii.
  • Lexical Analysis: The lexical analyzer will break down the entire code into individual tokens, such as identifiers, numbers, strings, and so on.
  • Semantic Analysis: The semantic analyzer will combine the tokens to abstract semantic tree and check its grammar correctness.
  • Static Analysis: In Clang, it used to analysis the source code to find out errors automatically.
  • IR Generation: Finally, the AST will be parsed to LLVM IR (intermediate representation).

SwiftC

The SwiftC is a Swift frontend compiler.

The main procedure:

  • Parse: Converts Swift code into raw AST.
  • Sematic Analysis: Checks types for the raw AST and converts it to standard type-checked AST.
  • Clang importer:
  • SIL Gen: Generates the SIL(Swift Intermediate Language) from the AST.
  • IR Generation: Finally, the SIL will be parsed to LLVM IR (intermediate representation).

The LLVM IR has three formats: text (pure text format easy for people reading, file extension is ..l), bitcode(binary format, file extension is .bc) and memory(memory format).

LLVM Backend

The LLVM backend procedure:

  • Optimize: Before assembling, the LLVM will do some optimizations. We can set up optimization level in Xcode settings (Build Settings -> Apple Clang - Code Generation -> Optimization Level). There are three optimization levels: -01, -03 and -0s. The LLVM uses Pass to do that and we can custom our own Pass for special needs.
  • Assemble: Generates target files (Mach-o).
  • Link: Links multiple target files to executable files.
